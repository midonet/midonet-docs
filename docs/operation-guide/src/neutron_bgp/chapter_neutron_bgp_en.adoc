[[neutron_bgp]]
= Neutron BGP (Dynamic Routing)

MidoNet’s implementation of Neutron BGP provides two different ways of
configuring BGP.

*Router Insertion*

In this mode, when you create a BGP speaker object, you specify the router to
which you want to associate it to. This does not match Neutron's
http://specs.openstack.org/openstack/neutron-specs/specs/mitaka/bgp-dynamic-routing.html[Dynamic Advertising Routes for Public Ranges]
specification, but matches MidoNet's BGP configuration more closely where you
configure BGP on a specific router. Only one router can be associated to a BGP
speaker, and only one BGP speaker can be associated with a router. This feature
is implemented as a Neutron vendor extension, `bgp-speaker-router-insertion`.
Router association is specified on creation, and cannot be updated.

When a BGP speaker is configured in this mode, invoking the
`add_gateway_network` API on that BGP speaker results in an error.

With this mode, any network added to the router that has a BGP speaker
associated, will have its route automatically advertised, including the extra
routes added.

*Non Router Insertion*

In this mode, when you create a BGP speaker object, you do not specify a router
ID to associate with. This matches the expected behavior of the reference
implementation API. This mode is used only when you want to advertise external
network subnet routes. This is useful when you have several edge routers in the
deployment handling different external networks. You can save API calls by just
creating a BGP speaker without any router association.

When a BGP speaker is configured in this mode, invoking the
`add_gateway_network` API on that BGP speaker tells the MidoNet plugin to
advertise a route to this external network. The gateway router is the router
that has the `gateway_ip` of the provided network's subnet allocated to. When
the plugin cannot locate the gateway router, it results in an error. Also, if
the gateway router already has a BGP speaker associated, it results in an error.

With this mode, all the external networks associated with a BGP speaker will be
advertised automatically.

Currently you have to choose one mode or the other and cannot go back and forth.
But in the future, we may enhance the model by allowing users to update the
`router_id` field of BGP Speaker.

== Creating a router, network and subnet

In this example, we use an edge router (router acting as the gateway on an
external network), but it applies to regular tenant routers as well.

Skip this step if you already have these. This is here just for completeness.

[source]
----
# neutron router-create EdgeRouter
----

Router ID: 14ce01e6-af80-11e5-aca9-6730c321a8c7

[source]
----
# neutron net-create --router:external True ExtNetwork
----

Network ID: cb98c61f-b299-4e66-8c29-0da8e4e0146d

[source]
----
# neutron subnet-create cb98c61f-b299-4e66-8c29-0da8e4e0146d 200.0.0.0/24
----

Subnet ID: d97e2ee8-f194-11e5-949d-0242ac110001

[source]
----
# neutron router-interface-add 14ce01e6-af80-11e5-aca9-6730c321a8c7 d97e2ee8-f194-11e5-949d-0242ac110001
----

== Configuring BGP with Router Association

=== Creating a BGP speaker

[source]
----
# POST http://api_server_url/bgp-speakers
   '{"bgp_speaker": {
      "tenant_id": "admin",
      "name": "BGP-Speaker",
      "local_as": 300,
      "ip_version": 4,
      "advertise_floating_ip_routes": False,
      "advertise_tenant_networks": True,
      "router_id": "14ce01e6-af80-11e5-aca9-6730c321a8c7"
   }'
----

BGP Speaker ID: ea57e7e8-a7a4-11e5-89c2-b78c120baeb9

The `advertise_floating_ip_routes` parameter determines whether external network
routes are advertised, and the `advertise_tenant_networks` parameter determines
whether non-external networks are advertised.

=== Updating a BGP Speaker

Only `name` can be updated.

[source]
----
# PUT http://api_server/bgp_speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9
{"name": "BGP-Speaker-changed"}
----

=== Creating a BGP peer

[source]
----
# POST http://api_server_url/bgp-peers
   '{"bgp_peer": {
      "tenant_id": "admin",
      "name": "BGP-Peer",
      "peer_ip”: "10.0.0.1",
      "remote_as”: 400,
      "auth_type”: "md5",
      "password": "$1$RzrnCAAt$FWS7sy1ZwWIc0ln7moO0W0"
   }'
----

BGP Peer ID: ba1fc7ca-f197-11e5-8b10-0242ac110001

=== Updating a BGP Peer

`name` and `password` can be updated.

[source]
----
# PUT http://api_server/bgp_peers/ba1fc7ca-f197-11e5-8b10-0242ac110001
{"name": "BGP-Peer-changed",
 "password": "$1$b6mXFzDF$KZ0pIqWZQN6DRp4tSUWj.0"}
----

=== Adding a BGP peer to a BGP Speaker

[source]
----
# PUT http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9/add_bgp_peer
{"bgp_peer_id": "ba1fc7ca-f197-11e5-8b10-0242ac110001"}
----

After this, the router will automatically advertise routes to all the networks
attached to it, including those that were already attached to the router.

== Configuring BGP without Router Association

=== Creating a BGP speaker

[source]
----
# POST  http://api_server_url/bgp-speakers
   '{"bgp_speaker": {
      "tenant_id": "admin",
      "name": "BGP-Speaker",
      "“local_as": 300,
      "ip_version": 4,
      "advertise_floating_ip_routes",
      "advertise_tenant_networks": True
   }'
----

BGP Speaker ID: ea57e7e8-a7a4-11e5-89c2-b78c120baeb9

The `advertise_floating_ip_routes` parameter indicates that external network
routes are advertised. In most cases, this should be `True` in this mode.

When `advertise_tenant_networks` is set to `True`, the routes to the tenant
networks are advertised. This implies that the private subnets of the tenants
are accessible from outside through the tenant routers.

=== Updating a BGP Speaker

Only `name` can be updated.

[source]
----
# PUT http://api_server/bgp_speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9
{"name": "BGP-Speaker-changed"}
----

=== Creating a BGP peer

[source]
----
# POST http://api_server_url/bgp-peers
   '{"bgp_peer": {
      "tenant_id": "admin",
      "name": "BGP-Peer",
      "peer_ip": “10.0.0.1”,
      "remote_as": 400,
      "auth_type": "md5",
      "password": "$1$RzrnCAAt$FWS7sy1ZwWIc0ln7moO0W0"
   }'
----

BGP Peer ID: ba1fc7ca-f197-11e5-8b10-0242ac110001

=== Updating a BGP Peer

`name` and `password` can be updated.

[source]
----
# PUT http://api_server/bgp_peers/ba1fc7ca-f197-11e5-8b10-0242ac110001
{"name": "BGP-Peer-changed",
 "password": "$1$b6mXFzDF$KZ0pIqWZQN6DRp4tSUWj.0"}
----

=== Adding a BGP peer to a BGP Speaker

[source]
----
# PUT http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9/add_bgp_peer
{"bgp_peer_id": "ba1fc7ca-f197-11e5-8b10-0242ac110001"}
----

=== Adding a gateway network

This API is only supported in the non-router association mode. If this API is
invoked on a BGP speaker that has a router association, an error will be
returned.

[source]
----
# PUT http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9/add_gateway_network
   '{"network_id": "cb98c61f-b299-4e66-8c29-0da8e4e0146d"}'
----

`network_id` must be an external network. After this API call, external network
CIDR (Floating IP) will be advertised.

=== Removing a gateway network

This API is only applicable if you created a gateway network (non-router
association case).

[source]
----
# PUT http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9/remove_gateway_network
   '{"network_id": "cb98c61f-b299-4e66-8c29-0da8e4e0146d"}'
----

=== Removing a BGP peer from a BGP Speaker

[source]
----
# PUT  http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9/remove_bgp_peer
   '{"bgp_peer_id": "ba1fc7ca-f197-11e5-8b10-0242ac110001"}'
----

=== Deleting a BGP Peer

[source]
----
# DELETE http://api_server_url/bgp-peers/ba1fc7ca-f197-11e5-8b10-0242ac110001
----

=== Deleting a BGP Speaker

[source]
----
# DELETE http://api_server_url/bgp-speakers/ea57e7e8-a7a4-11e5-89c2-b78c120baeb9
----
